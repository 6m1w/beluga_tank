## 设计

当时出过三个样板让你挑：纪实新闻风、沉浸深海风、博物馆展签风。最后选了**纪实新闻风**。

- 深夜蓝底色，全页只有一个强调色：卷尺黄，只用在尺寸和数字上（水缸尺寸、「20 平米」、3D 里的尺寸标注）。
- 笔记本上，左栏放文字，右边放水缸，两边互不遮挡。左栏内容多时可以单独滚动，滚动条是暗色细条。
- 手机上是「上 3D、下文字」：水缸占上半屏，下面依次是选馆、切换视角、正文。

```
笔记本（≥960px）                          手机
┌────────────┬───────────────────────┐    ┌─────────────┐
│ 页眉        │ 选馆 / 视角 / 声音     │    │ 页眉         │
├────────────┼───────────────────────┤    ├─────────────┤
│ 一辈子，    │                       │    │  3D 水缸     │
│ 20 平米。   │       3D 水缸         │    │ （约半屏）    │
│ 正文        │                       │    ├─────────────┤
│ 数据表      │                       │    │ 选馆 / 视角   │
│ 怎么看      │                       │    ├─────────────┤
└────────────┴───────────────────────┘    │ 标题 + 正文   │
                                          └─────────────┘
```

- 3D 镜头会根据画面区域的实际大小自动算远近，保证整个水缸和尺寸标注都在画面内。竖屏手机改从斜对角看，水缸能占满更多画面，尺寸标注的字也会跟着放大。

## 加载提速

| 项目 | 改版前 | 改版后 |
|---|---|---|
| 白鲸模型 | 11MB（4096 PNG 贴图，其中法线贴图就占 8MB） | 线上实际传输 238KB |
| 人物模型 | 7.3MB（还带一段用不到的 T-Pose 动作） | 线上实际传输 590KB |
| 背景音乐 3.7MB | 一打开页面就预先下载 | 用户打开声音后才下载 |
| Three.js | 从 unpkg 加载（国内慢） | 放进项目 `vendor/`，线上约 165KB |
| 样式 | Tailwind CDN 在浏览器里现场编译 | 直接写成 CSS，不再依赖外部 |
| 字体 | Google Fonts（国内经常打不开） | 系统字体 + 57KB 喜鹊宋体子集 |
| 显存 | 6 张 4096 贴图，约 500MB，手机上容易崩 | 不到 20MB |

另外几处让页面跑得更顺的改动：

- 页面和空水缸先出来，白鲸模型下载完后淡入，同时显示下载进度。人物模型等白鲸到位后才下载。
- 水缸玻璃原来用的材质每一帧都要多画一遍整个场景，换成了效果几乎一样的普通半透明材质。阴影计算原本没有物体在用，关掉了。
- 手机上画面清晰度最高按 2 倍屏计算（3 倍屏手机原来要多画一倍多的像素）。3D 画面滚出屏幕后自动暂停渲染。

模型压缩用的是 gltf-transform：贴图转成 WebP 并缩小（白鲸 1024、人物 512），模型几何数据用 meshopt 压缩。原始大模型已从仓库删除，git 历史里还能找回。

## 白鲸出水修复

**根因**：白鲸是「骨架带动网格」的动画模型。旧代码按原始网格（骨架还没带动时的样子）把白鲸摆到中心，但屏幕上画出来的是骨架带动以后的样子，两者差了很多：

- 实际画出来的身体比代码以为的位置**高约 1.9 米、往前约 1 米**。静止帧实测身体上下范围是 `y[1.28, 2.57]`，本该以 0 为中心。
- 13 秒的游泳动画里有一次甩头转身，身体会再往侧面、往上甩出去。
- 旧的游动范围是「缸底到半缸高」，按缸的尺寸打八折，没有考虑白鲸本身的体积，再加上 1.9 米的偏差，在 4–5 米高的缸里就会冒出水面。
- 每头白鲸的速度和起始位置都是随机的，所以会互相追尾、穿模。

**修法**：

1. 白鲸模型载入时，把整段游泳动画逐帧量 80 次，按真实画出来的身体重新对齐中心，并记下它占多大空间。
2. 上下方向用整段动画里的最大范围，保证任何时刻都不出水：身体中心只能在「缸底往上留出半个身子」到「水面往下留出半个身子」之间活动，水面比缸顶低 0.3 米。
3. 水平方向用平时游泳的典型身长和身宽，算出一条能在缸里转身的椭圆路线：哪一侧撞墙就收那一侧。如果用甩头那一瞬间的最大尺寸来算，在 5 米宽的缸里白鲸就根本没地方掉头了。
4. 所有白鲸在同一条路线上首尾等距排开，速度一致，所以不会追尾。如果一圈排不下，多出来的会分到另一层水深、反方向游（按现有 7 个馆的数据都不会用到这一层）。

**实测结果**：每个馆模拟游 60 秒，按骨架带动后的真实身体检查：

| 海洋馆 | 水缸 | 白鲸 | 离缸顶 | 离缸底 | 碰到玻璃的帧 |
|---|---|---|---|---|---|
| 北京海洋馆 | 20×5×5 | 1 | 0.58m | 0.31m | 4.2%（最多伸进 13cm） |
| 广州海洋馆 | 20×6×5 | 2 | 0.35m | 0.33m | 0.8% |
| 多彩贵州城 | 10×5×6 | 1 | 0.58m | 0.31m | 5.0%（最多伸进 16cm） |
| 三亚亚特兰蒂斯 | 14×8×6 | 2 | 0.37m | 0.28m | 0.4% |
| 长沙海底世界 | 15×10×10 | 3 | 0.34m | 0.39m | 0.6% |
| 大连老虎滩 | 16×5×4 | 3 | 0.37m | 0.19m | 2.5% |
| 成都极地 | 20×15×10 | 6 | 0.34m | 0.39m | 0.3% |

- 所有馆都不再出水。
- 白鲸之间：3,600 次检查里只有大连有 1 帧外框相碰。外框比身体大一圈，所以真实身体未必碰到。
- 已知小瑕疵：5 米宽的缸里，白鲸做甩头动作时鼻子偶尔会碰到玻璃。4 米长的白鲸在 5 米宽的缸里本来就很难掉头，这个瑕疵反而说明了缸有多窄，所以保留。

## 字体：喜鹊宋体简繁版

**为什么换**：

- 主要是为了各设备显示一致。原来写的是「系统宋体」（Songti SC），只有苹果设备上有。安卓和 Windows 会退回各自的默认字体，有的直接变成黑体，标题气质差别很大。现在标题字体跟着网页一起下载，所有人看到的都一样。
- 喜鹊宋体更细、更舒展，有书卷气，「一辈子，20 平米。」这种带叹息感的句子用它更合适。

**怎么用的**：

- 只用在页眉「海洋馆内的一生」和大标题上，正文、数据表、按钮保持系统字体。
- 这套字体只有常规体，没有粗体，所以关掉了浏览器自动生成的假粗体（`font-synthesis: none`）。假粗体会让笔画糊在一起。
- 字体文件只保留页面用到的 262 个字符，生成 `fonts/xique-song.woff2`，**57KB**（完整字体 6.7MB）。它和白鲸模型一起提前下载，没下完时先用系统宋体顶着，下完再换，不会出现一片空白。

**授权**：喜鹊宋体是商业字体，已购买商业授权，包括网页使用。仓库里只提交了子集文件，**完整字体文件不进仓库**，所以别人拿不到完整字库。

**以后改文案要注意**：如果加了页面上原本没有的新字（比如新增一个海洋馆），要重新生成一次字体子集，否则新字会显示成系统宋体，和别的字风格不一样：

```bash
pip3 install fonttools brotli          # 只需装一次
python3 scripts/subset_font.py         # 默认读取 ~/Library/Fonts/喜鹊宋体简繁版.ttf
```

脚本会读取 `index.html` 的正文和 `app.js` 里的中文（海洋馆名称等），重新生成子集，最后打印出字符数和文件大小。
